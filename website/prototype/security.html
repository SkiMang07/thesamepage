Security Statement

How we protect the data your organization trusts us with.

Effective August 25, 2026 · Last updated August 25, 2026

Your organization is storing its performance record, its team’s development history, and honest notes about real people in The Same Page. Here’s exactly how we protect it.

Data Storage

All data is stored in a PostgreSQL database hosted by Supabase on Amazon Web Services infrastructure.

Draft — confirm before publishing: Prism Tree’s statement names an exact AWS region (US-West-2, Oregon). Confirm your Supabase project’s region and I’ll state it here the same way, or drop the claim if it varies.

Encryption in Transit

All communication between your browser and The Same Page — both the frontend and the backend API — is encrypted using HTTPS/TLS. Unencrypted HTTP connections are not accepted.

Encryption at Rest

Standard encryption at rest is provided by our infrastructure (Supabase on AWS). Unlike some tools in this space, The Same Page does not store OAuth tokens or user-supplied API keys today, so there’s no separate secrets-encryption layer to describe — there’s nothing beyond the database itself that needs one.

Per-Organization Data Isolation

The Same Page uses Row-Level Security (RLS) enforced at the database layer by Supabase. Every query against your data includes a database-level policy check — your organization’s data is isolated from every other organization’s regardless of application-level logic, and what an individual account can see within your own organization is scoped the same way. This is a database-enforced constraint, not just a software guard.

Authentication

User authentication is handled by Supabase Auth, which verifies tokens on every authenticated API request — tokens are never trusted client-side only. Passwords are never stored in plaintext.

Rate Limiting

API endpoints are rate-limited to protect against abuse and runaway automation.

No Ads, No Tracking, No Data Selling

The Same Page contains no advertising SDKs, no third-party analytics trackers, and no ad pixels. We do not sell or share your data with data brokers, advertisers, or recruiters.

What We Don’t Do

  • We do not store credit card numbers (billing, if added in the future, will be handled by a PCI-compliant processor)
  • We do not use your organization’s data to train AI models beyond what’s described in our Privacy Policy
  • We do not sell or share data with recruiters, advertisers, or data brokers

Responsible Disclosure

If you discover a security vulnerability in The Same Page, please report it to us at andrewgodlew@gmail.com before disclosing it publicly. We will investigate and respond promptly.

For security-related questions, contact us at andrewgodlew@gmail.com.
